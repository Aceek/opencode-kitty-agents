# V1 Architecture

## Goals

- Present every relevant OpenCode child session in a Kitty split.
- Attach to the existing child session rather than creating another agent.
- Preserve focus on the orchestrator by default.
- Clean up managed windows safely when sessions disappear or the plugin stops.
- Keep session lifecycle logic independent from Kitty.
- Leave a narrow adapter seam for future presentation backends.

## Non-Goals

- OpenCode sidebar or TUI panel integration.
- Hyprland, tmux, WezTerm, or generic terminal support.
- Team communication, task orchestration, or agent prompt injection.
- Starting, stopping, or deleting OpenCode child sessions.
- Persisting recoverable control capabilities across process restarts.
- Automatically changing a user's Kitty layout.

## Core Contracts

```ts
type ChildSession = {
  id: string
  parentID: string
  directory: string
  title: string
  status: "idle" | "busy" | "retry"
}

type PresentationHandle = {
  backend: "kitty"
  windowID: number
  openedAt: number
}

interface PresentationAdapter {
  availability(): Promise<
    | { available: true }
    | { available: false; reason: string }
  >
  open(session: ChildSession): Promise<PresentationHandle>
  exists(handle: PresentationHandle): Promise<boolean>
  focus(handle: PresentationHandle): Promise<void>
  close(handle: PresentationHandle): Promise<void>
  dispose(): Promise<void>
}
```

The exact TypeScript shapes may evolve during implementation, but the ownership
boundary must remain: the session controller never invokes Kitty directly.

## State Model

The controller owns one record per child session:

```ts
type ManagedChild = {
  session: ChildSession
  presentation?: PresentationHandle
  desired: "open" | "closed"
  phase: "discovered" | "opening" | "open" | "closing" | "unavailable"
  lastError?: string
}
```

State mutations run through one serialized queue. SDK calls and Kitty commands
may execute asynchronously, but their resulting mutations re-enter the queue
and verify that the record is still current.

## Session Discovery

V1 tracks child sessions visible to the plugin's project-scoped OpenCode client.

- On `session.created`, accept sessions with a non-empty `parentID`.
- On `session.deleted`, remove the session and close its managed presentation.
- On `session.status`, update known sessions; reconcile unknown session IDs.
- At startup and periodically, call `session.list()` and filter by `parentID`.
- Fetch `session.status()` and normalize missing status for a known child to
  `idle`.

Reconciliation is authoritative for membership. Events reduce latency.

## Kitty Targeting

Capture and validate the origin identity at plugin initialization:

- `KITTY_PID`
- `KITTY_WINDOW_ID`
- `KITTY_LISTEN_ON`

All commands target stored numeric IDs:

```text
origin tab:  --match=window_id:<origin-window-id>
source:      --source-window=id:<origin-window-id>
placement:   --next-to=id:<origin-window-id>
child:       --match=id:<child-window-id>
```

Never target `active`, `recent`, `-1`, titles, or indices.

## Child Command

The Kitty adapter launches a trusted executable with an argv array equivalent
to:

```text
opencode attach <server-url> --dir <directory> --session <session-id>
```

Resolve the OpenCode executable once through a controlled mechanism. Do not use
`/bin/sh -c`. Inherit only authentication variables required by OpenCode attach
and avoid copying the complete environment through Kitty options.

## Layout Policy

V1 supports Kitty's `splits` layout only.

- Detect the originating tab layout through `kitten @ ls`.
- If it is not `splits`, report presentation unavailable and leave the layout
  unchanged.
- Default placement is a vertical split next to the orchestrator.
- Default child bias should be configurable and conservative.
- Additional children should use deterministic placement anchored to managed
  IDs, not whichever child is active.

The exact multi-child arrangement must be proven with an integration test
before becoming a public guarantee.

## Server Reachability

Read `ctx.serverUrl` at launch time. Probe `/global/health` with a short timeout
before opening a split.

If unreachable:

- keep the OpenCode child session untouched;
- do not create a Kitty window;
- record a non-sensitive unavailable reason;
- retry only through bounded reconciliation, not a tight loop.

## Cleanup

Cleanup is idempotent.

- Manual Kitty closure removes only the presentation handle.
- OpenCode session deletion closes the associated Kitty window if it exists.
- Plugin `dispose` stops timers, rejects new work, drains or cancels queued
  operations, and closes all managed Kitty windows with bounded concurrency.
- A missing Kitty window is success during cleanup.
- The plugin never deletes OpenCode sessions as cleanup.

## Logging

Log structured lifecycle transitions and sanitized failures. Never log:

- complete environment maps;
- `KITTY_LISTEN_ON` values;
- Kitty public keys or passwords;
- OpenCode server passwords;
- authentication headers;
- full command lines containing sensitive values.

## Extension Strategy

Future backends implement `PresentationAdapter` and their own availability
checks. Backend selection belongs in configuration. No backend-specific handle
may leak into the session tracker beyond the opaque presentation handle.
